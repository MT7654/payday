# Security

This app relies on the **Sites authentication gateway**. `app/chatgpt-auth.ts` consumes the gateway's `oai-authenticated-user-*` headers; those headers are not credentials that the Worker can independently verify. Only the gateway may set them. An alternate public Worker route that accepts caller-supplied identity headers would bypass authentication. The generated Wrangler configuration disables workers.dev and version-preview URLs. Hosted deployments must preserve that setting and prevent alternate routes around the gateway. Do not expose this Worker directly without replacing authentication with verified sessions or restricting ingress to the trusted gateway. Local simulated sign-in is development-only and must stay bound to loopback.

All personal state is scoped to the authenticated owner in parameterized D1 queries. Mutation routes require an exact matching Origin, reject non-same-origin Fetch Metadata when present, and require JSON for POST/PUT/PATCH. These checks follow the [OWASP origin and Fetch Metadata guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) and protect browser sessions from CSRF; they do not authenticate API clients. No CORS access is granted. Request bodies are bounded to 400 KB and 10 seconds. Changes to these rules should include negative tests.

AI credentials live in server secrets. OpenAI requests have a fixed HTTPS destination, refuse redirects, disable response storage, limit output tokens, and bound response bodies to 2 MB. Both discovery stages share a 90-second deadline. Public discovery and the conversational guide share a daily HMAC-derived client pseudonym based on the gateway-supplied IP address. They allow 40 requests per UTC day, 8 per minute and one in flight per pseudonym, plus a shared 250-request daily site ceiling. Missing/invalid client IP fails closed outside development. Use a private `RATE_LIMIT_SECRET`, or the existing OpenAI key as fallback; neither key nor raw IP is persisted. Shared networks share a quota. Requests rejected by a later quota check may already consume earlier counters, conservatively limiting usage. Completed and failed admitted requests both count. Old anonymous counters and expired anonymous leases are cleaned up on subsequent admitted traffic.

Database leases expire after 120 seconds if a worker exits unexpectedly; cleanup is conditional on the lease token so an old request cannot unlock a newer one. Deleting personal content retains revision and quota metadata. Request limits are not a spending guarantee: one research request can make multiple provider calls. Configure provider project budgets/alerts and gateway abuse protection before broader public rollout. The identity/IP header trust boundary must hold for anonymous limits as well as signed-in storage.

Returned HTTP responses add no-sniff, no-referrer, restricted device permissions, HTTPS HSTS, and a minimal CSP for object embedding, base URLs and forms. This CSP is compatible with current inline hydration; it is **not a complete script/XSS policy**. Frame policy remains the hosting gateway's responsibility so Sites embedding keeps working. Static assets served before Worker execution need equivalent host-level headers. Keep React text escaping; never render AI or merchant HTML directly.

Application diagnostics use a field allowlist. They exclude identities, headers, cookies, prompts, saved content, URLs, raw exceptions and provider bodies. Correlation IDs are generated by the server, never copied from client headers. Platform/framework logs have their own privacy and retention settings; see [operations](docs/operations.md). `store: false` is not a guarantee about provider abuse-monitoring retention.

## Maintenance and reporting

The prepared [CI workflow](docs/ci/checks.yml) runs tests, type checking, a production build and `npm audit --audit-level=high` with read-only repository permissions and pinned action commits once installed at `.github/workflows/checks.yml`. It is not active yet: the current GitHub OAuth credential lacks the `workflow` scope required to publish that file. Dependabot checks packages and actions weekly. Audit findings are dependency advisories, not proof that a specific app route is exploitable. Scoped overrides currently pin patched `sharp`/`undici` under Miniflare, `fflate` below 0.7.5, and the legacy Drizzle loader’s `esbuild`. Remove those overrides when upstream dependencies resolve to safe versions without them. Review dependency changes and compatibility before merging; do not bypass peer checks or use an unreviewed force update.

For a suspected vulnerability, use GitHub's **Report a vulnerability** option if enabled for this repository, or contact a repository maintainer privately. Include affected commit, reproduction steps and impact, without credentials or other users' data. Do not post sensitive reports in public issues. Maintainers should enable private vulnerability reporting and secret scanning where their GitHub plan supports them; this PR does not change account settings.
